### 后果

| 影响 | 说明 |

| **H05 覆盖 = 0 人** | 纯静态（C12）这条分支一次都没被测 |

### 但这不是全废 —— 它意外变成了一个受控对照

三份记录都指向 H06，等于：**同一份材料（C01 Next+Supabase）× 三种画像（非技术 / 半技术 / 全栈）**。
这恰好回答了比原计划更关键的一个问题：**输出会不会随画像适配？**

答案是：完全没有。三种人卡在三个完全不同的地方（见 §3.2）。

> **所以本轮数据要分两种用法**：
> - 当"三个案例各测一次"用 → **作废**，H05/H03 零覆盖。
> - 当"同一案例 × 三种画像"用 → **有效**，且信息量比原设计更高。
>
> 下文按第二种用法分析，并在每条结论后标注它的适用范围。

## 2. 按框架重算 p

| 步骤 | 值 |
|---|---|
| 有效份数 n | 3（三份都"进分母 = 是"，纪律执行 0 次违规） |
| 达标数 k | 1（R3） |
| 半步 | 1（R2）—— 不进分子 |
| 未达标 | 1（R1） |
| **p** | **1/3 = 0.33** |

**阈值对照（n=3）**：A 要 ≥2 人、C 是 1 人、B 是 0 人 → **情况 C**。

**覆盖规则**（若判 A 但"看不懂"≥2 人则降级）不触发：本来就是 C。

### 但必须写清楚这个 p 的强度

n=3、p=0.33 的 95% 置信区间约 **[6%, 79%]**，**横跨 A / C / B 三档**。
也就是说：判 C 是**按框架规程**判的，不是统计推断出来的。这个样本量能告诉你"没有明显成立"，但**不能**告诉你"明显不成立"。

### 新增一条覆盖检查（本轮暴露的缺口）

框架 §2 只查"人数够不够"，没查"案例覆盖够不够"。结果 3 个人看同一份材料，也会被算成 n=3 有效。
已补进框架（见 §7）。本轮实测：

| 检查项 | 要求 | 实测 | 结论 |
|---|---|---|---|
| 每个案例 ≥1 人 | H05 / H06 / H03 各 ≥1 | H05:0 ／ H06:3 ／ H03:0 | ❌ |
| 案例字段可信 | 名词能在该案例材料里搜到 | 3 份里 2 份错 | ❌ |

**因此本轮的结论只能写成："对 H06 这份材料成立"，不能写成"对输出层成立"。**

## 3. 三份里真正稳的信号（不依赖案例标注）

### 3.1 没有人从「引擎读出的约束」开始读（3/3）

| 记录 | 第一眼看哪里 |
|---|---|
| R1 | 主推方案名 → 立刻滑到底部看坑列表 |
| R2 | 五层表格 |
| R3 | 五层表格 + 备选方案扫技术栈名 |

3 个人、3 种画像，**没有一个从"用户原文"或"引擎读出的约束"开始**。

这直接打到一个假设上：我们把"约束读对了没"当作产品的信任基础（`confidence`、`inferred_capabilities`、`inference_evidence` 都是为它做的），但**真人根本不看那张表**。他们直接从"给我什么"开始看。

> 适用范围：这条**不受案例标注影响**，因为三份看的都是同一份材料，行为一致。

### 3.2 同一份材料，三种画像卡在三个地方

| 画像 | 第一步的形态 | 卡在哪 | 他的原话 |
|---|---|---|---|
| **非技术**（R1） | 退回搜教程 | **看不懂名词 + 没有连接关系的画面** | "我知道这五个名字每个是干嘛的了，但是第一步点哪里、代码写在哪、怎么把前端和数据库连一块儿，我脑子里完全没画面" |
| **半技术**（R2） | 先去评估（搜稳定性、找 boilerplate 看结构） | **前端技术栈跨度**（Python 背景） | "让我为了做个界面去啃 React、App Router 还有 TypeScript，我怕前端调样式和状态管理就把我的热情耗光了" |
| **全栈**（R3） | 直接执行（`npx create-next-app` + 建 Supabase project） | **嫌重、嫌绑死** | "太重了，而且被 Serverless 绑得太死……我更习惯直接一台 5 刀的 VPS 起个单机 SQLite" |

**梯度非常整齐**：达标率随技术背景单调上升（全栈 1/1 → 半技术半步 → 非技术未达标）。
第一步的形态也是单调的：**命令 → 评估 → 搜教程**。

这说明输出的门槛是**技术背景**，而不是"某一句话写得不够清楚"。
换句话说：现在这份材料是"写给会写代码的人看的"，非技术/半技术读者被挡在门外。

> 适用范围：这条**恰恰因为三份都是 H06 才成立**——同一材料、不同画像，是干净的对照。
> 但每格 n=1，只能当**假设**，不能当结论。

### 3.3 「五层表格」是唯一的注意力中心，也是卡点中心（3/3）

| 记录 | 在五层表格上的行为 |
|---|---|
| R1 | 停顿约 15 秒，明显皱眉，滚轮来回搓；从坑列表**回滚**到五层表格 |
| R2 | 从备选方案**回滚**到五层表格对比前后端 |
| R3 | 看表格时笑了（"又是经典全家桶"） |

3 个人都在它上面花了最多时间，2 个人为它回滚。
**改它的杠杆最大**——但改成什么样，取决于"为什么卡"，而三个人的"为什么"完全不同（见 §3.2）。

## 4. 逐份归因（按框架 §5.2 的顺序）

### R1 → **B1 看不懂**

- ① 第 3 题点出架构名词（Next.js / Vercel / PostgreSQL）→ **命中，判 B1**
- 佐证：第 2 题"不知道从哪下手……第一步点哪里、代码写在哪、怎么连起来，脑子里完全没画面"
- 补充：他自发问"Supabase 是类似飞书多维表格那种东西吗" —— 这是**在用自己的经验做类比**，不是没兴趣。这类用户不是不能转化，是缺"翻译"。

### R2 → **能力不匹配**（框架里的 B0 类，但本轮只有 1 人，不作废）

- ① 第 3 题只有实现细节词（RLS、service_role），没有架构名词 → 不判 B1
- ② 第 2 题不是"不知道从哪下手"，是"卡在 Next.js 和前端生态上" → 不判 B1
- ③ 第 2 题没说"太重/不想用"，说的是"我怕把热情耗光" → 不判 B2
- → 落 `能力不匹配`

**但这条归因有一个前提被破坏了**：R2 是 Python 型选手（数据分析/算法），H06 的原始用户画像是 **JS/TS 80%**。
把一份为 JS 型用户生成的方案给 Python 型选手看，得到"前端跨度大"是**必然结果**，不是产品缺陷。

> 真正该问的是：如果引擎拿到 R2 的真实画像（Python 熟练、SQL 熟练、不熟前端），
> 会不会给出 C03（Next.js + FastAPI）这类**复用他 Python 底子**的方案？
> 本轮没有测这个 —— 因为材料是固定案例，不是按他的画像现算的。

### R3 → **B2 不认同架构**

- ③ 第 3 题"全都看得懂"（只有 RLS/连接池这类实现细节），第 2 题明确"太重了 / 被 Serverless 绑死 / 更习惯 VPS + SQLite" → **命中，判 B2**

**但这条的证伪价值最低**：给一个 5 年全栈看"新手向的全栈模板"，他说"太重"是可预期的。
他说"太重"不代表产品缺一个轻量选项，只代表**这份材料不该给他看**。

> 顺带记一条 R3 的自发信息：他提到"直接一台 5 刀的 VPS 起个单机 SQLite"。
> 这是一个**闭集里没有的形态**（自托管单机 + SQLite），但它是"更轻"，不是"更简单"，
> 对非技术用户反而更难。**不要因为这一条去加自托管模板**，那会加错人群。

## 5. 哪个结论能拿去指导动作，哪个不能

| 候选结论 | 能不能动 | 理由 |
|---|---|---|
| 加 C13（纯静态/无框架） | ❌ **不能** | R3 的"太重"是"给全栈看新手方案"的产物，不是"缺选项"的证据。加 C13 只会让 R1 看到更多他看不懂的名字 |
| 调 base_scores | ❌ **不能** | 三份里没有一份是"分数排错了"——R1 是看不懂，R2 是跨栈，R3 是偏好 |
| 改输出格式（五层表格加"连接关系"） | ⚠️ **可做，但现在做会归因不清** | R1 的卡点确实精确落在五层表格上，但这个卡点里混着"材料错配"（给他看了带 DB 的全栈方案，而他需要的是纯静态）。改完 p 变了，也说不清是格式好了还是材料对了 |
| **补样本，做画像 × 案例配对** | ✅ **唯一现在该做的** | 案例覆盖 1/3、案例字段 2/3 错，任何产品动作都建在流沙上 |

**一句话：本轮最该记的不是 p=0.33，是"3 个人看的是同一份材料"。**

## 6. 下一步：R4 / R5 怎么配

### 配对表

| 编号 | 画像 | 案例 | 为什么这么配 | 要验什么 |
|---|---|---|---|---|
| **R4** | 非技术 / 半技术 | **H05**（纯静态 C12） | R1 想做的"垂直领域案例库/导航站"本来就该匹配纯静态；本轮他被错配到了带 DB 的方案 | 去掉数据库和 Supabase 之后，非技术的人还会不会卡在"怎么连起来" |
| **R5** | 半技术（Python 型） | **H03**（不出方案） | H03 一次都没被测，而"我什么都不说清你就不给方案"是最容易被当成敷衍的行为 | 被拒绝时，是觉得"在帮我"还是"在敷衍我" |

### 两条硬约束（写死，别改）

1. **新样本必须"画像 ↔ 案例"匹配**，不能再出现"非技术看带 DB 的全栈方案"。
2. **每份记录必须现场记下他复述出的 ≥2 个技术名词**，访谈后 30 秒去材料里搜一遍。搜不到 = 案例字段错，该份按实际材料重新归类。

### 补完之后怎么算

```
n = 5（假设 5 份都有效）
案例覆盖：H05 ≥1、H06 ≥3、H03 ≥1  ✅ 通过 §2.5
p = k / 5
  ≥ 0.60（3 人）→ A
  0.20–0.60（2 人）→ C
  ≤ 0.20（≤1 人）→ B，再按 §5.2 分因
```

**如果补完 R4/R5 之后，"非技术 + 纯静态"这一格仍然未达标** —— 那时候才有资格说"输出格式对非技术用户不成立"，也才轮到改格式。改的时候只改一处：五层表格下方加一行「**先动哪个 + 数据怎么流**」（因为 3/3 的人都把注意力放在那张表上，且 R1 明确说缺的就是"连接关系的画面"）。
