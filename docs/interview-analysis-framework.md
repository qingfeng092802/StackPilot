# 访谈归因框架（M1 · 访谈回来后使用）

> 输入：`docs/interview-record-template.md` 填好的 3–5 份记录 + §8 汇总表
> 输出：一个分支结论（A / B1 / B2 / B0 / C）+ 一份具体动作清单
> **本框架不写代码，手填即可。** 代码与 PRD 已冻结，本阶段不改 `scoring.ts` / `combos.json`。

---

## 1. 只取 4 个数

从每份记录里取 4 个值，其余全部不看（观察栏只在归因时当证据用，不参与计数）：

| 字段 | 取值 | 来自模板 |
|---|---|---|
| `画像` | 非技术 / 半技术 / 全栈 | §3 |
| `达标` | 达标 / 半步 / 未达标 | §5 |
| `主因` | 看不懂 / 不认同架构 / 不信任 / 能力不匹配 / 没有动机 / 其他 | §6 |
| `进分母` | 是 / 否 | §7 |

---

## 2. 第一步：算通过率 p

```
n = 进分母 = 是 的份数
k = 其中 达标 的份数          ← 半步不算
p = k / n                     ← 保留两位小数
```

**`n` 的合法性**（不满足就别往下算，先去补人）：

| 情况 | 处理 |
|---|---|
| n < 3 | 不分析。3 份是最低限度，少于 3 份连方向都看不出来 |
| 有份记录「没按要求先给方案」 | 该份 `进分母 = 否`，但保留为参考 |
| 有份记录「没看完材料」 | 该份 `进分母 = 否` |
| 有效 n < 3 但总访谈 ≥5 | 样本流程有问题，先修访谈流程，不修产品 |

### 2.5 案例覆盖检查（第一轮暴露的缺口）

**人数够 ≠ 样本够。** 5 个人看同一份材料，你测的是"一份材料的 5 种反应"，不是"3 个案例的覆盖"。
不查这一条，n 会被虚高。

| 检查项 | 要求 | 不满足时 |
|---|---|---|
| **每案例 ≥1 人** | H05 / H06 / H03 各至少 1 人 | 结论只能写"对 X 案例成立"，不能写"对输出层成立" |
| **案例字段可信** | 记录里出现的技术名词，必须在该案例材料里真实存在 | 该份案例字段作废，按实际材料重新归类 |

**核对方法（30 秒）**：拿受访者复述出的 ≥2 个技术名词，去 `output-validation-preview.md` 对应案例段落里搜。
搜不到 → 他看的不是这份材料。

> 真实案例：第一轮 3 份记录里，R1 声称看 H05、R3 声称看 H03，但两人都提到了
> Supabase / RLS / 连接池 —— 这三个词在 H05 和 H03 里**一次都没出现**。
> 实际三人看的都是 H06。结果是 H05 和 H03 零覆盖，p 只能对 H06 成立。

## 3. 第二步：走决策树

```
                        p = k / n
                             │
        ┌────────────────────┼────────────────────┐
        │                    │                    │
     p ≥ 0.60            0.20 < p < 0.60        p ≤ 0.20
        │                    │                    │
      情况 A               情况 C              情况 B
   输出层假设成立        混合，分而治之      输出层假设不成立
        │                    │                    │
        │                    │           ┌────────┴────────┐
        │                    │       先排除 B0        再分 B1 / B2
        │                    │       样本问题        归因（见 §5）
        ▼                    ▼                    ▼
  M1 第二阶段            A 的动作 +          B1 改输出格式
  （算基线 / 接 LLM）    B 的归因各做一半     B2 补 C13 或调分
```

**阈值换算成具体人数**（省得每次算）：

| n | A（≥0.60） | C | B（≤0.20） |
|---|---|---|---|
| 3 | 2 人及以上 | 1 人 | 0 人 |
| 4 | 3 人及以上 | 1–2 人 | 0 人 |
| 5 | 3 人及以上 | 2 人 | 1 人及以下 |

> **覆盖规则（Override）**：若走出的结论是 A，但 `主因 = 看不懂` 的人数 **≥ 2**，
> 则**强制降级为 C**。理由：能说出第一步的人会动，看不懂的人不会动；
> 说明"输出层假设"没被推翻，但"输出格式"有硬伤，不能带着这个硬伤进 M1 第二阶段。

## 4. 情况 A：输出层假设成立（p ≥ 0.60）

### 结论怎么写

写「**方向性支持**」，不写「验证成功」。n=5 时 p=0.60 的 95% 置信区间约 **[23%, 88%]**，
n=3 时 2/3 的区间更宽。这个样本量能区分"明显成立"和"明显不成立"，测不出细节差异。

正确写法：
> 5 人中 3 人能说出具体第一步（p=0.60），方向性支持"给出方案能促使人动手"，样本小，不作效果承诺。

错误写法：
> 验证通过，用户认可度 60%。（"认可"是错词，我们测的是动作不是认可）

### 动作清单

| # | 动作 | 说明 |
|---|---|---|
| A1 | 进入 M1 第二阶段 | 算命中率基线（重跑 D1 双集，此时才允许动基线） |
| A2 | 接 LLM 生成 | 把 `output-validation-preview.md` 里"引擎的输出"那一段当**格式规范**，让 LLM 按这个结构生成 |
| A3 | 把达标者的"第一步"原话收集成清单 | 3–5 条真实的第一步，用来做 LLM 的输出校验：生成结果必须能让人接上这些动作 |
| A4 | 不动模板、不动分数 | A 分支**不允许**顺手加 C13 或调 base_scores，会污染下一轮归因 |

### A 分支**不要**做的事

- 不要因为"p=0.60 还不错"就去扩大访谈到 20 人 —— 边际信息很低，先做 A2
- 不要把"能说出第一步"当成"选型准确" —— 这是两个指标，混了就是上一轮反复纠正过的错

## 5. 情况 B：输出层假设不成立（p ≤ 0.20）

### 5.1 先排除 B0（样本问题）

`主因 = 没有动机` 或 `能力不匹配` 的人数 **≥ 2** → 判 **B0**。

| 判定 | 动作 |
|---|---|
| **B0 样本问题** | **整批数据作废，不修产品。** 换一批人重做。 |
| 只有 1 人属 B0 | 剔除该份，用剩下的重算 p（回到 §2） |

B0 的典型信号：对方说"我其实没这个需求 / 我就随便问问 / 我连 JS 都不会"。
这类人不是目标用户，他的"未达标"不能归因给产品。**先怀疑样本，再怀疑产品。**

### 5.2 再分 B1 / B2（归因优先级）

对每一份"未达标"的记录，按顺序判，**命中即停**：

```
① 第 3 题点出了架构名词？
   （Next.js / Supabase / Vercel / PostgreSQL / Edge Functions）
   → 是 → 判 B1 看不懂        【架构名词都没看懂，不可能形成架构判断】
   → 否 ↓

② 第 2 题说"不知道从哪下手"，但第 3 题说不出具体不懂的词？
   → 是 → 判 B1 看不懂        【认知负荷过载，不是偏好问题】
   → 否 ↓

③ 第 2 题明确说"太重 / 不想用 X / 我想要纯静态"，
   且第 3 题只有实现细节词（RLS / 连接池 / service_role）？
   → 是 → 判 B2 不认同架构    【看懂了，但方案不是他要的形态】
   → 否 ↓

④ 第 2 题说"这方案靠谱吗 / 会不会白学 / 出问题谁管"？
   → 是 → 判 B3 不信任（溢出类）
   → 否 → 判 其他，写进备注
```

> **优先级为什么是"看不懂 > 不认同架构"**：
> 看懂了才有资格不认同。如果他连 Next.js 是什么都不知道却说"太重了"，
> 那是道听途说的印象，不是架构偏好 —— 按 B2 去加模板，等于给看不懂的人再塞一套他更看不懂的东西。

### 5.3 B1：看不懂 → 改输出格式（不动模板）

**判据加固**：看"看不懂"的人**集中在哪个画像组**。

| 分布 | 含义 | 改什么 |
|---|---|---|
| 集中在**非技术/半技术**组 | 材料默认读者有技术背景 | 改**解释层**：术语首次出现加一句人话 |
| 集中在**全栈**组 | 不是术语问题，是信息组织问题 | 改**结构层**：删掉冗余层级、把结论前置 |

**动作清单（按性价比排序，先做前两条就够）**

| # | 动作 | 成本 | 验证方式 |
|---|---|---|---|
| B1-a | 主推方案名后面加一行「它是什么 / 它不是什么」 | 低 | 同一批人重看，只问第 1 题 |
| B1-b | 五层表格折叠成三行（前端 / 后端 / 数据库），AI 层和部署层并入备注 | 低 | 同上 |
| B1-c | 架构名词首次出现时括号解释（Next.js = 一个能同时写页面和服务端的框架） | 中 | 同上 |
| B1-d | 坑列表前面加一句"如果你只记一件事，记这条" | 低 | 同上 |

**B1 分支绝对不要做的事**：

- **不要加 C13**。模板数量解决不了"看不懂"，只会让选项更多、更看不懂
- **不要调 base_scores**。分数不是他卡住的原因
- **不要两个动作一起改**。改一处、重测、再改下一处，否则下一轮无法归因

### 5.4 B2：不认同架构 → 先分清"缺选项"还是"分数错"

| 他的原话形态 | 判断 | 动作 |
|---|---|---|
| "我想要纯静态 / 不要后端，但你只给了 Next.js" | **缺选项** | 补 **C13**（纯 HTML/JS 或 Astro 静态） |
| "Next.js 也能做，但你不该把它排第一" | **分数错** | 调 `base_scores` 或 `fit_rules` |
| "我不想用 Supabase，想自己管数据库" | **缺选项**（自建分支不够显眼） | 检查 C02/C09 为什么没进 Top2，可能被硬过滤误杀 |

**B2 分支的前置条件：需要解冻。** 当前代码冻结，B2 是唯一允许解冻的分支，且：

- 一次**只加一套模板**（C13），不同时调分
- 加完必须重跑 `check-consistency`（73 项 + 新增断言）与 D1 双集，确认 H02/H05/H08 的判定标签变化
- 加完**不改 PRD 的承诺边界**，只更新模板数与附录 F

> 提醒：C13 能让 H02/H05/H08 从 PARTIAL_HIT 变成 HIT（框架层对上），
> 但这是**命中率**的收益，不是**输出侧**的收益。B2 加 C13 的理由必须是"用户不接受现有形态"，
> 不能是"顺便把命中率刷好看"。

### 5.5 B3（溢出类）：不信任

用户任务里没列这一类，但访谈一定会出现（"这方案靠谱吗 / 会不会白学"）。

| 信号人数 | 处理 |
|---|---|
| ≥ 2 人 | 这是**独立的第三类问题**，既不是格式也不是架构。动作：在方案里加「这套东西的生命周期」一段（谁在维护、多久会过时、走了怎么迁） |
| 1 人 | 记入备注，不动作 |

## 6. 情况 C：混合（0.20 < p < 0.60）

不整体改，**按组拆**。先把 5 份记录按 `达标` 分成两组，各自归因：

| 组 | 归因 | 动作 |
|---|---|---|
| 达标组（k 人） | 他们接上了什么？共同点是什么？ | 把这批人的"第一步"原话提炼成**输出模板的骨架**，A2 时直接复用 |
| 未达标组（n−k 人） | 走 §5.2 的 ①②③④ 归因 | 只修占比最高的那一类，且只修一处 |

**C 分支的判定上限**：只允许做**一处**改动，然后重测同一批人（n≥3）。
改两处以上 → 下一轮 p 变了也不知道是谁的功劳。

**C 分支什么时候能升级为 A**：重测后 p ≥ 0.60 且"看不懂"人数 ≤ 1。

## 7. 这个样本量能得出什么、不能得出什么

| 能 | 不能 |
|---|---|
| 区分"明显成立"（≥3/5）和"明显不成立"（≤1/5） | 测出 50% 和 60% 的差别 |
| 定位**主因类型**（看不懂 / 不认同 / 不信任） | 给出各类原因的**占比** |
| 发现材料里**具体的**卡点词、卡点段落 | 预测大盘用户的通过率 |
| 决定下一步做 A2 还是改格式 | 宣称"验证成功"或"证伪" |

n=5、p=0.20 时 95% 区间约 **[4%, 62%]** —— 与 p=0.60 的 [23%, 88%] **大幅重叠**。
也就是说：**小样本下 A 和 B 在统计上分不太开**，所以结论只能写成"方向"，不能写成"结论"。
真正的验收要等 M1 第二阶段用更大的 D1 双集来算。

## 8. 反模式（这一节比上面所有规则都重要）

| # | 反模式 | 为什么错 | 正确做法 |
|---|---|---|---|
| 1 | 把"输出侧成立"当成"选型准确" | 两个指标，样本不同、口径不同 | 分开记，分开报 |
| 2 | 看到 B 就同时改格式 + 加模板 | 两个变量一起动，下一轮无法归因 | 一次只改一处，改完重测 |
| 3 | 用"用户说挺好"当达标 | 好评不是动作，社交礼貌不是信号 | 只认"具体第一步" |
| 4 | 把"半步"算进分子凑数 | 半步是决策动作不是建设动作，凑数会让 A 分支虚高 | 半步单独计数，只做辅助 |
| 5 | 样本问题当成产品问题 | B0 会让你去改一个没坏的东西 | 先排除 B0，再归因 |
| 6 | 看不懂的人说"太重"就判 B2 | 没看懂就没有架构偏好，只有印象 | 按 §5.2 的优先级判 |
| 7 | 为了把 p 做上去而挑人 | 访谈变成找认同，数据归零 | 按画像配比找人，不挑 |

## 9. 一页纸判定表（打印带走）

| 步骤 | 做什么 | 得到 |
|---|---|---|
| 1 | 数有效份数 n（剔除未按纪律的） | n |
| 2 | 数达标数 k（半步不算） | k |
| 3 | 算 p = k / n | p |
| 4 | 对照 §3 阈值表 | A / C / B |
| 5 | 若 A 但"看不懂" ≥ 2 人 | 降级为 C |
| 6 | 若 B：先数"没有动机 + 能力不匹配"，≥ 2 → B0 | B0 / 继续 |
| 7 | 逐份走 §5.2 的 ①②③④ | B1 / B2 / B3 |
| 8 | 按分支取对应动作清单 | 下一步 |

**填完这一页，只写一句话结论**，格式固定：

> n=＿，k=＿，p=＿ → 情况 ＿ ｜ 主因：＿＿（＿ 人）｜ 下一步只做：＿＿
