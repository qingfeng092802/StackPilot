# 调查问题表（M1 · 第二轮访谈用）

> 配套：`docs/interview-record-template.md`（记录用）／`docs/output-validation-preview.md`（材料）
> 本表是**提问用**的：按顺序念，答案填进模板。
> 代码冻结中，本表不涉及任何代码改动。

---

## 0. 怎么用

| 场景 | 用哪几节 | 耗时 |
|---|---|---|
| **发帖 / 私信筛人** | Part A（可直接整段复制发出去） | 对方 2 分钟 |
| **正式访谈（R4 / R5）** | Part A → B → C → D → 填模板 | 10–15 分钟 |
| **只想要一份分发问卷** | Part A + Part B，不加 Part D | 对方 5 分钟 |

**核心原则：问题顺序不能乱。** 画像判定（Part B）必须在给材料**之前**，案例核对（D4）必须在给材料**之后**。顺序反了，答案就被材料污染了。

---

## 1. 材料发放规则（上一轮错配就出在这里）

上一轮 3 个人看的都是 H06，案例字段却写成 H05 / H06 / H03 —— 大概率是发放环节出的问题。三条硬规矩：

1. **只打印要给他看的那一个案例**，不要把整份 `output-validation-preview.md` 给他（否则他会翻到别的案例，你不知道他在评哪一份）。
2. **每页页脚印上案例编号**（`H05` / `H06` / `H03`），访谈结束当场看页脚核对。这是物理防错，比事后回忆可靠。
3. **不要给**：本问题表、记录模板、分析框架、任何解释性备注。

## Part A · 招募筛选（3 题，可直接发出去）

> 发帖/私信原文，可直接复制：

> 我在做一个工具：你说清楚想做什么，它给出"用什么技术做、为什么这么选"的方案。
> 想找几个人帮我看 10 分钟，我会按你的需求给一份方案，你告诉我哪里看不懂、会不会真的动手。
> 不推销、不收费、不留联系方式也行。愿意的话回我三个问题：
>
> **A1. 你手上有没有一个想做但还没开始的东西？一句话说说是什么。**
> **A2. 这个东西你打算自己写代码，还是找人写 / 用现成工具拼？**
> **A3. 你现在最卡的是"不知道用什么技术"，还是"知道用什么但不会写"？**

### 筛人判定

| 回答 | 判定 | 处理 |
|---|---|---|
| A1 说得出具体东西（"一个 XX 站 / 一个 XX 工具"） | 目标用户 | 继续 |
| A1 说"还没想好 / 就是随便看看" | 无动机 | **不约**，会污染 B0 |
| A2 说"找人写" | 非目标 | 不约（他不做技术决策） |
| **A3 说"不知道用什么技术"** | **正中靶心** | 优先约 |
| **A3 说"知道用什么但不会写"** | **不是目标用户** | 不约。我们要解决的是选型和架构判断，不是教写代码 |
| A3 说"两个都卡" | 可用 | 约，但要记下来（他会把"不会写"混进"看不懂"） |

> A3 是整份表最有效的筛子。答"知道用什么但不会写"的人，看完方案一定说"挺好但我做不出来"——
> 那不是产品的错，是我们找错人了。

## Part B · 画像判定（5 题，给材料**之前**问）

> **不要问"你觉得自己是初级还是高级"** —— 自我归类不可靠（R1 自称运营，但天天用 Cursor 聊需求）。
> 只问行为，用行为判画像。

| # | 问题（照读） | 记什么 |
|---|---|---|
| B1 | 你最近一次自己动手让一段代码跑起来，是什么时候？做了什么？ | 有没有真的跑过东西 |
| B2 | 你电脑上装过 Node.js 或者 Python 吗？装过的话，用它跑过什么？ | 环境证据 |
| B3 | 有没有把一个东西放到网上、别人点链接就能打开？ | 部署证据（最关键） |
| B4 | 你最熟的语言/工具是什么？用它做过最复杂的东西是什么？ | 技能深度 |
| B5 | 这个东西你打算一个人做，还是有别人一起？ | 团队规模（影响方案取舍） |

### 判定表（按 B3 优先，B1/B2 次之）

| 画像 | 判定条件 |
|---|---|
| **非技术** | B3 没有；B1 基本没有或只有"改过表格公式/低代码"；B4 说不出编程语言 |
| **半技术** | B1 有、B2 有（写过脚本/分析/SQL），但 **B3 没有**（没独立部署过带登录的 Web 应用） |
| **全栈** | **B3 有**，且部署过的是完整 Web 应用（前端 + 后端 + 数据库） |

> 边界情况：B3 有但只是"把静态页传到 GitHub Pages" → 算**半技术**，不算全栈。
> 记在模板「画像依据」里，写清楚是哪一条证据支撑的。

## Part C · 案例分配矩阵

> 分配错了，后面所有分析都白做。**按画像查表，不要凭感觉挑。**

| 画像 | 分配案例 | 为什么 |
|---|---|---|
| **非技术** | **H05**（纯静态 C12） | 最轻的方案。要验的是：**最轻的那一套，非技术的人看不看得懂** |
| **半技术（Python 型）** | **H03**（不出方案） | 补上唯一没被测的行为：被拒绝时会不会觉得在敷衍 |
| **全栈** | **H06**（C01 全栈） | 与 R3 同材料，可做前后对照 |

### 招到重复画像时怎么分

| 情况 | 处理 |
|---|---|
| 招到 2 个非技术 | 一个看 H05，一个看 H03（桌面端需求，非技术也能判断"你做不了"这句话伤不伤人） |
| 招到 2 个半技术 | 一个看 H03，一个看 H05（半技术看纯静态，验证"会不会觉得太简陋"） |
| 招到 2 个全栈 | 一个看 H06（对照 R3），一个看 H05（全栈看纯静态，验证会不会觉得"这也叫方案"） |
| 招到的人画像不明 | 先问 B1–B3 再定，**不要先给材料再补问画像** |

## Part D · 正式访谈问题表（10–15 分钟）

### 时间轴

| 时间 | 做什么 |
|---|---|
| 0:00–1:00 | D1 开场（照读） |
| 1:00–3:00 | 给材料，**闭嘴**，让他自己看 |
| 3:00–4:30 | D2 通用三题 |
| 4:30–7:00 | D3 追问（按分支，**每题只追一次**） |
| 7:00–7:30 | D4 案例核对（趁他还在看材料） |

### D1 · 开场（照读，不要自由发挥）

> "我在验证一个想法，不是卖东西。这是一份给你这种需求的架构建议，你先自己看两分钟，我不解释，看不懂的地方就是它的问题不是你的问题。看完我问三个问题，大概十分钟。"

三个必须做到：说"验证想法"不说"我做的产品"／明确"我不解释"／明确"看不懂是它的问题"。

---

### D2 · 通用三题（**逐字念，不许改词**）

| # | 问题（原样问出） | 记什么（对应模板） |
|---|---|---|
| **Q1** | **"你看完这个方案，今晚会去做的第一步具体是什么？"** | §4 第 1 题 + §5 判定 |
| **Q2** | **"如果你现在要放弃这个方案，最可能是因为哪个卡点？"** | §4 第 2 题 + §6 主因 |
| **Q3** | **"方案里有没有哪个词/哪句话你没看懂？"** | §4 第 3 题 + §6 主因 |

> 不许做的事：不追问"为什么"、不补一句"是不是因为……"、不说"这个其实很简单"、不在他停顿 3 秒内接话。

---

### D3 · 追问分支（**每题只追一次**，追完仍含糊就记未达标）

**Q1 的追问**（按他的回答类型选一条，只选一条）：

| 他答成什么样 | 追这一句 |
|---|---|
| "先学一下 X" / "先了解一下" | "今晚具体打开哪个网站、做什么动作？" |
| "再想想" / "先调研一下" | "那今晚会打开什么？" |
| "找个人问问" | "问完之后你会打开什么？" |
| 说出了具体动作 | **不追**，直接记达标 |

**Q2 的追问**（只在他说得笼统时用）：

| 他答成什么样 | 追这一句 |
|---|---|
| "就是感觉不太行" | "是哪个部分让你觉得不太行，能指一下吗？" |
| "太难了" | "难在'看不懂它说什么'，还是'看懂了但做不出来'？"（这句是分因的关键，**不要跳过**） |
| 说得出具体卡点 | **不追** |

**Q3 的追问**（只在他说"都懂"时用一次）：

| 他答成什么样 | 追这一句 |
|---|---|
| "都懂" / "没有" | "那这个方案里，你最不确定它到底是干什么的是哪一个？" |

---

### D4 · 案例核对（访谈者的自查，30 秒）

> 趁他还在看材料时问，**不要事后靠回忆**。

> **"你还记得方案里提到哪几个工具的名字吗？随便说两三个。"**

| 步骤 | 动作 |
|---|---|
| 1 | 把他说的名词记进模板「他复述出的技术名词」 |
| 2 | 访谈后 30 秒，拿这些词去 `output-validation-preview.md` 对应案例段落里搜 |
| 3 | **搜不到 → 案例字段填错了**，按实际材料重新归类，并检查是不是发放环节出错 |
| 4 | 再看一眼他手上那页的**页脚编号** |

**速查（哪些词只在哪个案例里出现）**：

| 名词 | H05 | H06 | H03 |
|---|---|---|---|
| Next.js / Vercel / Edge Functions | ✅ | ✅ | ❌ |
| Supabase / RLS / service_role / 连接池 | ❌ | ✅ | ❌ |
| PostgreSQL | ❌ | ✅ | 仅用户原文 |

> 只要他说出 **Supabase / RLS / 连接池 / service_role** 中任意一个 → 他看的是 **H06**。
> 只要他说出 **GitHub Pages / 纯静态 / 不需要后端** → 他看的是 **H05**。
> 只要他说 **"它没给我方案" / "它说做不了"** → 他看的是 **H03**。

---

### D5 · 案例专属题（每组 3 题，**跳过与通用题重复的**）

#### 若他看的是 H05（纯静态 C12）

| # | 问题 | 备注 |
|---|---|---|
| H05-1 | "这份方案说'你不需要后端，纯静态就够了'——这和你原本想的一样吗？如果不一样，你更信谁，为什么？" | 必问 |
| ~~H05-2~~ | ~~"今晚你会照着它开始吗？第一步你会打开什么？"~~ | **跳过**，与 Q1 重复，重复问会让他觉得你没在听 |
| H05-3 | "如果它推荐的前端是 React，而你其实想用 Vue，你会觉得这份方案没用了，还是仍然有用（只是换掉前端）？" | 必问 |

#### 若他看的是 H06（C01 全栈）

| # | 问题 | 备注 |
|---|---|---|
| H06-1 | "我们在原文里读到'同一个浏览器下次打开能接着上次听'，于是判断'数据要留存、需要数据库'。这个判断对吗？" | 必问（验推断） |
| H06-2 | "方案给你的是 Next.js + Supabase（带数据库）。你会照着开始吗？如果不会，是'要学的东西太多'还是'你不认同这个架构'？" | 若 Q1 已达标则跳过 |
| H06-3 | "如果换成'纯静态 + 浏览器本地存'，你能接受吗？不能的话，缺的是什么功能？" | 必问（测能不能降档） |

#### 若他看的是 H03（不出方案）

| # | 问题 | 备注 |
|---|---|---|
| H03-1 | "你的需求是桌面客户端，我们直接说了'当前覆盖不了、给不出方案'。你觉得这是在帮你，还是在敷衍你？" | **本轮核心**，必问 |
| H03-2 | "如果只能给你一个网页版方案（功能会打折），你会考虑改形态吗？还是宁可自己做桌面端？" | 必问 |
| H03-3 | "你愿意留个联系方式，等我们支持桌面端时通知你吗？" | 必问（测需求收集有没有人响应） |

---

### D6 · 收尾（2 题，为下一轮留人）

| # | 问题 | 为什么问 |
|---|---|---|
| D6-1 | "如果我按你的意见改完，再给你看一次，你愿意吗？" | 下一轮要做**配对重测**（同一个人看新旧两版），现在不留人，到时候只能换新样本，对照就断了 |
| D6-2 | "你身边有没有跟你情况差不多、也在想做点东西的人？" | 滚雪球招募，比发帖精准得多 |

## Part E · 黑名单（这些问题一律不要问）

| 不要问 | 为什么 |
|---|---|
| "你觉得这个方案好不好 / 有没有用 / 靠不靠谱？" | 只会得到"挺好的"，且诱导他说好话 |
| "你是不是觉得太难了？" | 等于把答案递给他 |
| "你会为此付费吗？" | n=5 时全是噪音，还会让他觉得你在卖东西 |
| "你会推荐给朋友吗？"（NPS） | 同上，且和"会不会动手"无关 |
| "你觉得自己是初级还是高级？" | 自我归类不可靠，用 Part B 的行为题判 |
| "如果我们加上 XX 功能，你会用吗？" | 假想题，答案不可信。**只问已经发生的行为** |

## Part F · 一页速查卡（打印带走）

```
【发材料前】
□ 只打印这一个案例，页脚印了编号
□ Part B 五题问完，画像判了，案例按矩阵分配
□ 开场话术照读，说了"我不解释"

□ 闭嘴 60 秒，不打破沉默

【三题，逐字】

Q2 如果你现在要放弃这个方案，最可能是因为哪个卡点？

【追问，每题只一次】

H05 → 只问 1 和 3（第 2 题与 Q1 重复，跳过）

【收尾】
"改完再给你看一次，你愿意吗？"
```

## 与上一轮的两个差别

| 项 | 上一轮 | 这一轮 |
|---|---|---|
| 画像判定 | 事后凭印象填 | **给材料前用 5 道行为题判**，防止"非技术看全栈方案" |
| 案例核对 | 靠访谈者回忆 | **让他复述名词 + 看页脚编号**，30 秒可验 |
| 筛人 | 没筛，A3 那类人被算进分母 | Part A 先筛掉"知道用什么但不会写"的人 |
| 留人 | 没留 | D6-1 留人做配对重测 |
