> **这份文件不是产品文档，是访谈材料。** 里面的方案全部由 `scripts/gen-preview.ts`
> 从引擎真实输出生成，没有任何人工润色。引擎改了，重跑脚本即可。
>
> 生成时间：2026-10-23 ｜ 样本来源：D1 盲标（V2EX /go/create 真实产品帖）

## 一、这份材料要验证什么

产品假设是「**用户需要技术栈选型，并且愿意照着给出的方案开始**」。
D1 只证明了前半句（需求存在），后半句一条证据都没有。这三个案例分别压一个假设：

| 案例 | 场景类型 | 压的假设 |
|---|---|---|
| H05 | 纯静态、零后端（新加的 C12 覆盖） | **架构判断被接受**：用户认不认"你不需要后端" |
| H06 | 带数据库、真实取舍复杂 | **愿意照着开始**：认不认架构 + 会不会真动手 |
| H03 | 桌面端，闭集覆盖不了 | **拒绝的方式被接受**：说"没有"比硬凑更可信吗 |

每个案例的 3 个问题，第 1 题压"认知是否对齐"，第 2 题压"行动意愿"，第 3 题压"边界是否可接受"。

## 二、访谈纪律（重要）

1. **不要解释我们的实现**。不要提"打分引擎""闭集""fit 乘数"。用户看到的就是一份方案。
2. **先让用户自己读完整份，再开口**。中途打断会把你的措辞混进他的理解。
3. **记录原话，不要记录你的总结**。"他说还行"没有信息量，"他说'Supabase 我听都没听过'"才有。
4. **不要引导**。问"你会照着开始吗"，不要问"你是不是觉得这个方案挺清楚的"。
5. **不要替用户回答第 2 题**。哪怕你觉得他肯定不会做，也要等他自己说。

**主推：C12 Vite + React 纯静态（零后端）** —— 4.33 分

> 所有逻辑跑在浏览器里，构建成静态文件丢到 Pages 上，没有服务器也就没有服务器成本和运维

| 层 | 组件 |
|---|---|
| 前端 | Vite + React（FE-04） |
| 接口层 | （不需要） |
| 数据库 | （不需要） |
| AI 层 | （不需要） |
| 部署 | Cloudflare Pages（DP-02） |

**新手最容易踩的坑**

- 没有服务端就没有任何数据共享：你和同事在不同设备上看到的东西不一样，所有状态只活在自己浏览器里，清缓存就没了
- 纯客户端渲染不利于 SEO。靠搜索流量获客的工具站（比如尺码计算器、单位换算）要考虑静态生成或干脆用纯 HTML，否则搜索引擎抓不到内容
- GitHub Pages 的项目页路径带 /repo/ 前缀，构建产物的 base 没配对会整站白屏或刷新 404

**什么时候该离开这套**：当需要登录、多设备同步、或要把数据存在服务端时，离开这套改用 C01；需要 AI 但不想把 key 暴露在前端时，改用 C11


---

**备选（换了架构形态）：C11 Next.js 纯前端 + Edge Functions（无数据库）** —— 4.33 分

> 不需要登录、不需要存数据时，一个前端加一个 AI key 就能上线

| 层 | 组件 |
|---|---|
| 前端 | Next.js（FE-01） |
| 接口层 | Next.js Route Handlers（BE-01） |
| 数据库 | （不需要） |
| AI 层 | Vercel AI SDK（AI-01） |
| 部署 | Cloudflare Pages（DP-02） |

**新手最容易踩的坑**

- 没有数据库意味着刷新页面数据就没了：收藏、草稿这类功能只能存 localStorage，换设备不同步
- Edge Functions 有执行时长限制，大文件解析、长文本生成这类长任务会被截断，要改成流式或分段
- API key 写进前端环境变量等于公开，必须走 Edge Function 代理，并加一层最简限流

**什么时候该离开这套**：当需要登录、需要多用户共享数据、或需要按用户做配额时，离开这套，改用 C01

### 5. 要问用户的 3 个问题

1. 这份方案说"你不需要后端，纯静态就够了"——这和你原本想的一样吗？如果不一样，你更信谁，为什么？
2. 今晚你会照着它开始吗？如果会，第一步你会打开什么、敲什么；如果不会，是哪一句话让你停下来了？
3. 如果它推荐的前端是 React，而你其实想用 Vue，你会觉得这份方案没用了，还是仍然有用（只是换掉前端）？

### 1. 用户原始输入（原文，未改写）

> 我平时要同时连 MySQL、PostgreSQL、Redis，偶尔还有 ClickHouse 和 SQL Server。用过的几个工具开起来慢、吃内存，我就想要一个原生、用起来舒服的。想做的功能：连十几种数据库、表格就地编辑（先暂存预览 SQL 再提交）、可视化改表结构、ER 图、SQL 补全、执行计划、导入导出、SSH 隧道、SSL，连接可设只读或写前确认。就自己用，顺便开源。现在只做 macOS，后面有精力再加 Windows。

|---|---|
| 交付形态 | 桌面客户端 |
| 几个人做 | 1 |

| 做来干什么 | 作品集 —— 看起来专业，但必须能跑通 |

### 3. 引擎的输出：**不出方案**

| 项 | 内容 |
|---|---|
| 判定 | 超出模板库覆盖范围（`coverage_status = uncovered` ｜ `confidence = medium`） |
| 给用户的话 | 当前模板库未覆盖你的场景 |
| 是否收集需求 | 是（记进"待支持形态"清单） |

**为什么不给方案**：Rust + GPUI（GPU 渲染原生界面），无 Electron / WebView

> 这不是"算不出来"，是"闭集里确实没有这类模板"。硬凑一个网页方案给桌面端需求，
> 比直接说"没有"更伤信任。

### 4. 要问用户的 3 个问题

1. 你的需求是桌面客户端，我们直接说了"当前覆盖不了、给不出方案"。你觉得这是在帮你，还是在敷衍你？
2. 如果只能给你一个网页版方案（功能会打折），你会考虑改形态吗？还是宁可自己做桌面端？
3. 你愿意留个联系方式，等我们支持桌面端时通知你吗？（这是在测"需求收集"这个动作有没有人响应）
