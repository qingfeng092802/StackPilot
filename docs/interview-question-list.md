# 访谈问题清单

## 一、筛人

1. 你手上有没有一个想做但还没开始的东西？一句话说说是什么。
2. 这个东西你打算自己写代码，还是找人写 / 用现成工具拼？
3. 你现在最卡的是"不知道用什么技术"，还是"知道用什么但不会写"？

## 二、给材料前

4. 你最近一次自己动手让一段代码跑起来，是什么时候？做了什么？
5. 你电脑上装过 Node.js 或者 Python 吗？装过的话，用它跑过什么？
6. 有没有把一个东西放到网上、别人点链接就能打开？
7. 你最熟的语言 / 工具是什么？用它做过最复杂的东西是什么？
8. 这个东西你打算一个人做，还是有别人一起？

## 三、给材料后

9. 你看完这个方案，今晚会去做的第一步具体是什么？
   - 若含糊 → 今晚具体打开哪个网站、做什么动作？
   - 若说"再想想 / 先调研" → 那今晚会打开什么？
   - 若说"找个人问问" → 问完之后你会打开什么？

10. 如果你现在要放弃这个方案，最可能是因为哪个卡点？
    - 若说"太难了" → 难在"看不懂它说什么"，还是"看懂了但做不出来"？
    - 若说"感觉不太行" → 是哪个部分让你觉得不太行，能指一下吗？

11. 方案里有没有哪个词 / 哪句话你没看懂？
    - 若说"都懂 / 没有" → 那这个方案里，你最不确定它到底是干什么的是哪一个？

12. 你还记得方案里提到哪几个工具的名字吗？随便说两三个。

## 四、案例专属题

### 看的是 H05

13. 这份方案说"你不需要后端，纯静态就够了"——这和你原本想的一样吗？如果不一样，你更信谁，为什么？
14. 如果它推荐的前端是 React，而你其实想用 Vue，你会觉得这份方案没用了，还是仍然有用（只是换掉前端）？

### 看的是 H06

15. 我们在原文里读到"同一个浏览器下次打开能接着上次听"，于是判断"数据要留存、需要数据库"。这个判断对吗？
16. 方案给你的是 Next.js + Supabase（带数据库）。你会照着开始吗？如果不会，是"要学的东西太多"还是"你不认同这个架构"？
17. 如果换成"纯静态 + 浏览器本地存"，你能接受吗？不能的话，缺的是什么功能？

### 看的是 H03

18. 你的需求是桌面客户端，我们直接说了"当前覆盖不了、给不出方案"。你觉得这是在帮你，还是在敷衍你？
19. 如果只能给你一个网页版方案（功能会打折），你会考虑改形态吗？还是宁可自己做桌面端？
20. 你愿意留个联系方式，等我们支持桌面端时通知你吗？

## 五、收尾

21. 如果我按你的意见改完，再给你看一次，你愿意吗？
22. 你身边有没有跟你情况差不多、也在想做点东西的人？
