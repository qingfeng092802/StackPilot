## 1. 访谈前一天：把地址跑通

### 方案 A：公网地址

1. 部署（步骤见 `docs/deploy-safe.md`），拿到 `https://xxx` 地址。
2. 打开它，确认能看到「◈ StackPilot」标题和输入框。
3. 输入一句话点「开始选型」，确认能出追问卡片。
4. 把地址发到自己微信收藏，访谈当天直接转发给受访者。

### 方案 B：本地（受访者在你旁边）

```bash
cd D:\StackPilot
npm install            # 第一次才需要
npm run dev            # 会自动 build，然后启动
```

看到这三行就对了：

```
  已从 .env.local 载入 3 个变量（覆盖同名环境变量）
  key   已加载（…xxxx，长度 35）
  M3 渲染页已启动： http://localhost:8787
```

然后浏览器打开 `http://localhost:8787`。

> 如果报 `✗ 没找到 .env.local`：`cp .env.example .env.local`，把 `ANTHROPIC_API_KEY`
> 换成真实值。**不要**用 `node --env-file=.env.local` 启动——它不覆盖已存在的同名变量，
> 会一直用错 key 并报 401（踩过）。

### 方案 C：本地 + 内网穿透（受访者在远端）

先按方案 B 跑起来，然后**另开一个终端**：

```bash
npx localtunnel --port 8787
# 或：ngrok http 8787
```

它会给一个 `https://xxx.loca.lt` 之类的地址，把这个发给受访者。
**注意**：这个地址指向你的电脑，**访谈期间你的电脑不能关、不能睡眠**。

## 2. 访谈前 5 分钟：预热（必做，别省）

**为什么必须做**：服务有冷启动（首次请求 5–10 秒）；如果用的是会休眠的托管，
第一次打开可能要等十几秒甚至看到一个"启动中"的过渡页。
受访者撞上这个，会以为产品是坏的——你的记录就废了。

### 预热步骤（2 分钟）

1. 打开 `<地址>`，**等到页面完整出现**（能看到输入框和"开始选型"按钮）。
2. 输入框里打一句：`我想做个记账的小程序`，点「开始选型」。
3. 等到**出现追问卡片**（不是空白、不是转圈）。
4. **不要点生成**，直接刷新页面清空。
5. 记下这次从打开到出卡片的秒数，填在记录表顶部「预热耗时」。

### 预热的三条硬标准（任一不满足就别开始访谈）

- [ ] 页面顶部有「◈ StackPilot」——不是"工作空间已停止"或"正在启动"
- [ ] 输入框能打字
- [ ] 点「开始选型」能在 10 秒内出追问卡片

> 如果是托管平台，**访谈期间最好别让页面空置太久**。间隔超过 15 分钟，
> 下一场之前再预热一次。

## 3. 案例分配：三组，各给一份原文

### 3.1 分哪三份、为什么

| 组 | 案例 | 建议人数 | 期望看到的结果 | 为什么选它 |
|---|---|---|---|---|
| **A** | **H01** 中文名生成器 | 3 | **C11** Next.js 纯前端 + Edge Functions（无数据库） | 有 AI 能力、无数据库，和 C12 区分得开 |
| **B** | **H06** 网页电台 | 4 | **C12** Vite + React 纯静态（零后端） | 原文明确说"只存浏览器里"，是**极性修复**的最佳展示案例 |
| **C** | **H03** 数据库客户端 | 3 | **不出方案**（提示当前覆盖不了） | 唯一能测"拒绝"路径的案例，且不给方案是正确行为 |

**为什么不按原计划用 H02 + H06 + H03**：我实跑了 10 个案例的解析层，H02 和 H06
在解析结果上**完全一样**（都是 `delivery=web` + `required_capabilities=["no_persistence"]`），
Top1 也都是 C12。用它们当两组，等于用两份材料测同一件事，案例覆盖是假的。
换成 H01 才能拿到第三种结果。

### 3.2 一个必须先知道的限制（会影响你怎么解读数据）

我实跑了全部 10 个案例，结论是：**原文的差异在解析层被压得很扁。**

| 案例 | 解析层读到什么 | 完整链路的 Top1 |
|---|---|---|
| H01 | `web` + `ai` | **C11** |
| H04 | `selfhost` + `ai` | C11 |
| H02 / H05 / H06 / H08 | `web` +（`no_persistence` 或空） | **C12** |
| H03 / H07 / H09 / H10 | 覆盖不了 | **不出方案** |

也就是说：**10 个案例最终只落到 3 种结果**。
原因是解析层通常只从原文里读到 2 项（交付形态 + 一两个能力），剩下 7 项全靠追问三题。

所以：

> **Top1 的差异，主要来自受访者对"追问三题"的回答，不是来自原文。**
> 这意味着**你不能替他答题，也不能给所有人统一答案**——
> 一旦统一，三组就变成一组，案例覆盖归零。

### 3.3 三份原文（直接复制粘贴给受访者）

**A 组 · H01**

```
我朋友是教外国小朋友学中文的老师，她给班上孩子取中文名特别费劲：不能简单音译，得考虑字义、文化背景、读音好不好听、符不符合中国人命名习惯。每次取一个名字要查字典翻古诗想半天，家长还不一定满意。我想给她做个网站，输入英文名能生成几个候选中文名，每个都带拼音、字义解释和文化背景，能按性别和风格筛，还能收藏喜欢的。就她和她同事用，量很小。
```

**B 组 · H06**

```
上班路上爱听广播，但经常听一半就到公司了；干活时也想听点新鲜的。我想做个网页：打开按一下就随机掉进世界上某个城市的电台，同一个浏览器下次打开能接着上次听；按「下一站」随机换台，能只听高码率；能读到曲名的直接显示，读不到的点一下就识别；收藏的歌能跳到音乐 App 去搜。星图按流派铺开可以拖着逛，也有地球视图。不要账号、不要广告，收藏只存浏览器里。
```

**C 组 · H03**

```
我平时要同时连 MySQL、PostgreSQL、Redis，偶尔还有 ClickHouse 和 SQL Server。用过的几个工具开起来慢、吃内存，我就想要一个原生、用起来舒服的。想做的功能：连十几种数据库、表格就地编辑（先暂存预览 SQL 再提交）、可视化改表结构、ER 图、SQL 补全、执行计划、导入导出、SSH 隧道、SSL，连接可设只读或写前确认。就自己用，顺便开源。现在只做 macOS，后面有精力再加 Windows。
```

> **怎么给他**：发微信文字，让他自己复制粘贴进输入框。
> **不要你替他打字**——粘贴速度、有没有改字、有没有删掉几句，都是信息。

### 3.4 期望结果的健康基线（访谈前先自己跑一遍）

自己按标准答法跑一次，确认产品没坏：

| 案例 | 答法 | 应看到 |
|---|---|---|
| H01 | 三题答「JS 熟练 / 对外做产品 / 只有我一个」 | Top1 = **C11**，置信度 medium，约 5 秒出结果 |
| H06 | 同上 | Top1 = **C12**，置信度 medium |
| H03 | —— | 直接显示"覆盖不了"，**2 秒内**、**不问任何问题**、不调模型 |

跑完对得上，说明产品是健康的，可以开始访谈。
对不上就别开始——先查是不是用了旧版本（`npm run build` 重新构建一次）。

> H03 那 2 秒不是卡住了，是**设计如此**：超出覆盖范围就短路，不浪费模型调用。
> 访谈时如果受访者问"怎么没反应"，就告诉他"它在告诉你这个形态它不接"。

## 4. 现场流程（8 步，每步一句话）

| # | 你做什么 | 你记什么 |
|---|---|---|
| 1 | 确认他屏幕上是「◈ StackPilot」 | 预热耗时（§2） |
| 2 | 把案例原文发给他，**让他自己粘** | 他有没有改字、删句、加自己的话 |
| 3 | 他点「开始选型」 | 输入到出卡片几秒 |
| 4 | 看页面上"我读到了…"那几行 | **逐字抄**（这是解析层的唯一证据） |
| 5 | 看问了哪几个问题 | 抄问题字段名；他答了几个、跳过几个 |
| 6 | **让他自己答，不替他选** | 他犹豫的地方、问"这个选哪个"的地方 |
| 7 | 点生成，等方案出来 | Top1 名称 + "第一步"那句话，逐字抄 |
| 8 | **停 60 秒不说话** | 他鼠标停在哪、盯着哪段看最久 |

然后进 §5 的提问。

> 第 6 步是最容易破功的地方：他一问"这个选哪个"，你脱口而出"选第一个"，
> 这一份记录就废了。正确回应只有一句：**"你觉得呢？"**

## 5. 把"网页上的输入"和"D4 三问"接起来记

### 5.1 对照关系

| 网页上发生的 | 记录表哪一栏 | 用来判断什么 |
|---|---|---|
| 他粘进去的原文 | `输入原文` | 这是**他的表达**，不是他的需求 |
| "我读到了…"那几行 | `产品读到的` | **解析层有没有读对** |
| 问了哪几个问题 | `追问了几个` | 缺的信息有没有被问到 |
| 他答的选项 | `他的答案` | Top1 的差异主要来自这里 |
| 方案里的 Top1 + 第一步 | `引擎 Top1` / `方案的第一步` | 输出层给了什么 |
| **D4 三问**的回答 | `第 1 问` | **他会不会动**（唯一进 p 的判据） |

### 5.2 为什么必须两边都记

只看 D4 三问，你只能知道"他没动"，不知道为什么。两边一对，三种情况分得清清楚楚：

| 网页输入 | D4 三问 | 结论 |
|---|---|---|
| 读对了 | 说不出第一步 | **输出层问题**（方案没接上） |
| **读错了** | 说不出第一步 | **解析层问题**（前提就错了，方案再漂亮也没用） |
| 读对了 | 说出了具体动作 | **达标**，且可以问他"哪句话让你想到这个动作" |

### 5.3 D4 三问（逐字照读）

**第 1 问（主问句）**

> 你看完这个方案，今晚会去做的第一步具体是什么？

三个追问（只在他答得含糊时用）：

- 含糊 → 「今晚具体打开哪个网站、做什么动作？」
- 「再想想 / 先调研」→ 「那今晚会打开什么？」
- 「找个人问问」→ 「问完之后你会打开什么？」

**第 2 问**

> 如果你现在要放弃这个方案，最可能是因为哪个卡点？

**第 3 问**

> 方案里有没有哪个词 / 哪句话你没看懂？

**第 4 问（只在第 1 问没拿到具体动作时问）**

> 你会照着开始吗？不会的话，卡在哪？

> ⚠️ **顺序不能改**。「你会照着开始吗」是可以答"不会"的问题，先问等于递台阶，
> 你就再也拿不到第 1 问那个真正有信息量的答案（"我今晚会打开 supabase.com 注册"）。

## 6. 解析错误怎么记（M4 新增的失败模式）

这是 M0 那轮测不到的东西——那轮材料是我们给的，没有解析这一步。

### 6.1 四种错误，分开记

| 类型 | 长什么样 | 怎么记 | 严重度 |
|---|---|---|---|
| **漏读** | 原文明确说了 A，产品没读到 | `漏读：原文说了「要能导出 Excel」，没读到` | 中 |
| **极性读反** | 原文说"不要 A"，产品读成"要 A" | `极性读反：原文「只存浏览器」，被读成 data_persistence` | **最高** |
| **幻觉** | 原文没说 A，产品自己填了 A | `幻觉：原文没提登录，读到了 auth` | **高**（违反"你没说的我不替你猜"） |
| **解析失败** | 页面直接说"没能把你的描述转成结构" | `解析失败：stage=xxx，detail=…` | 中（有降级路径） |

### 6.2 怎么快速发现

第 4 步抄"我读到了…"的时候，**用眼睛对一遍原文**：

- 页面上出现的每一项，原文里有没有对应的词？没有 → **幻觉**
- 原文里明显说了的（"要登录""能导出""手机上看"），页面上没有 → **漏读**
- 原文里有"不要 / 不需要 / 只…就行"这类否定，页面上却出现了对应能力 → **极性读反**

### 6.3 三条记录纪律

1. **解析错误单独记，不要改 p 的分子分母。**
   p 测的是"输出层假设"，解析层的 bug 修完之后 p 会变，两轮数据不可比。
2. **但要在总结里单独列一条 issue**，写清：哪个案例、哪句话、被读成了什么。
3. **如果是极性读反，当场截屏。** 这类 bug 最容易在复盘时被"记不清了"糊过去。

### 6.4 已知的两个"看起来像错、其实是对的"

访谈时容易误判，先记住：

| 现象 | 是不是 bug | 说明 |
|---|---|---|
| **H06 原文说"只存浏览器里"，产品给的是纯静态 C12，但作者实际用了 SQLite** | **不是 bug** | 用户说的和作者做的不一致。产品按**用户说的**算。这一条要单独问他（见下） |
| H05 / H08 的 `dropped` 里出现 `required_capabilities.no_persistence` | **不是 bug** | evidence 校验没过（原文里找不到能逐字对上的依据），按"宁可漏、多问一句"丢掉了 |

针对第一条，**B 组（H06）必须加问一句**：

> 我们按原文理解成"数据只存在浏览器里，不需要服务器和数据库"，所以给的是纯静态方案。
> 这个理解对吗？如果其实需要换设备也能看到，你会怎么改这句话？

他的回答是 M4 最有价值的一条数据：**说明用户表达和真实需求之间的差距有多大**。

## 7. 如果必须继续用旧沙箱（下策，先读代价）

旧链接已下线，原因是产物里带着明文 API key。

**要用它，前提是两个都得满足**：

1. 先在模型后台**轮换**旧 key（旧的那把到现在还有效，实测能正常调用）；
2. 用 `scripts/local-gateway.mjs` 把真 key 留在本机，产物里只放可撤销令牌
   （步骤见 `docs/deploy-safe.md` 附录 A）。

**做不到这两条，就不要用。** 把带 key 的产物挂到公网，等于把额度交给任何拿到链接的人。

另外它还有两个和 key 无关的坑，终测时一定会遇到：

- 空闲 10–15 分钟自动停止，**HTTP 请求唤不醒**，只能手动点「立即启动」或重新部署；
- 网关改写所有路径，所以必须设 `SP_SINGLE_PATH=1`。

## 8. 备用方案：公网打不开时怎么在本地跑

### 8.1 最快路径（3 条命令）

```bash
cd D:\StackPilot
npm install
npm run dev
```

浏览器打开 `http://localhost:8787`。

### 8.2 常见报错对照

| 报错 | 原因 | 怎么办 |
|---|---|---|
| `✗ 没找到 .env.local` | 没配凭据 | `cp .env.example .env.local`，填 `ANTHROPIC_API_KEY` |
| `✗ 启动失败：缺少环境变量 ANTHROPIC_API_KEY` | `.env.local` 里那行是空的 | 填上真实 key |
| `✗ 找不到 build/server.js` | 没构建 | `npm run build`（`npm run dev` 会自动做） |
| `EADDRINUSE :8787` | 8787 被占了（多半是上次没关干净） | `PORT=8788 npm run dev`，然后开 `localhost:8788` |
| 接口报 `401 凭据无效` | key 错 / 过期，或用了 `--env-file` 导致读的是旧 key | 看启动日志里 `key 已加载（…后四位）`，确认是不是你粘的那把 |
| 页面能开，点按钮没反应 | 浏览器缓存了旧页面 | Ctrl+F5 硬刷新 |

### 8.3 受访者在远端怎么办

本地地址他打不开。两条路：

```bash
# 临时穿透（访谈结束就关）
npx localtunnel --port 8787
```

或者干脆按 `docs/deploy-safe.md` 部署一次（10 分钟，之后一直能用，比每次穿透省事）。

> 穿透地址会变，**每次访谈前重新生成并把新地址发给他**。
> 访谈期间你的电脑不能睡眠——把电源计划改成"永不睡眠"。

## 10. 急救表

| 现象 | 原因 | 怎么办 |
|---|---|---|
