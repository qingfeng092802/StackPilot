## 0. 这一轮和 M0 那轮的区别

M0 测的是**"给一份现成方案，人会不会动"**——材料是打印好、指定好案例的。
这一轮测的是**"人自己说一句话，产品能不能把他推到动手"**——材料是他自己输入的大白话。

差别不只是"换成网页了"，而是**多了一层可能失败的地方**：

| 环节 | M0 | 终测 | 失败长什么样 |
|---|---|---|---|
| 输入 | 无（材料是我们给的） | 用户自己说 | 说不到点子上 / 说得太笼统 |
| 解析 | 无 | 模型读成约束向量 | **读错、读空、读反**（极性 bug 就是这一类） |
| 追问 | 无 | 缺字段时反问 | 问了不关键的 / 问太多 / 问得让人烦 |
| 选型 | 固定 | 引擎排名 | 选了个不合适的 |
| 解释 | 固定文案 | 模型生成 + 校验 | 说人话 / 说套话 / 被校验退回模板 |
| 第一步 | 材料里写着 | 引擎给 + 模型润色 | 给了但接不上 |

所以这一轮**多一个必须记录的字段：解析层干了什么**（读了哪几项、问了哪几个、丢了什么）。
M0 的记录表里没有这一列，因为它测不到。

> ⚠️ 这条很关键：如果用户的"未达标"是因为**解析层把他的原话读错了**，
> 那是产品 bug，不是"输出层假设不成立"。混在一起记，下一轮会去改错地方。

## 1. 测试目标

### 要回答的一个问题

**用户自己说一句需求，走完整个产品，能不能说出今晚就能做的第一步？**

### 要拿到的四个数

| 数 | 从哪取 | 用途 |
|---|---|---|
| `达标 / 半步 / 未达标` | §3 主问句 | 算 p，决定 M1 验收 |
| `主因` | §3 第 2、3 问 + 第 4 问 | 归因：看不懂 / 不认同 / 不信任 / 能力不匹配 / 没有动机 / 解析错误 |
| `画像` | §4 记录表 | 分组看：问题是出在"说人话"还是"选型" |
| `解析偏差` | §4 记录表「解析层」一栏 | 区分"产品 bug"和"假设不成立" |

### 明确不测

| 不测 | 为什么 |
|---|---|
| 满意度 / NPS / "你觉得有没有用" | n=10 时全是噪音，且会诱导对方说好话 |
| 愿不愿意付费 | 这个阶段问这个，等于把访谈变成推销 |
| **选型准不准** | 这是 D1 基线的指标（`docs/D1-数据采集与闭集覆盖诊断.md`），样本和口径都不同。混着报就是 framework §8 反模式 #1 |
| 界面好不好看 | 想改样式不用等终测，随时能改 |

## 2. 测试环境与流程

### 环境

- 用**用户自己的电脑和浏览器**，不要用你的电脑。他平时的输入法、网络、屏幕大小都是变量，不能替他抹平。
- 提前把链接发到他微信，让他自己点开。**不要替他打开、不要替他滚动页面。**
- 全程录屏（手机拍屏幕也行），重点录**他的鼠标停在哪里、停了多久**。
- 你坐在旁边但**不碰键盘**。他要输入就让他自己输入，打字慢也等。

> ⚠️ **开场前 5 分钟必须自己先打开一次链接（预热）。**
> 服务有冷启动；如果你用的是会休眠的托管（免费实例、或旧的 WorkBuddy 沙箱），
> 停止时打开链接看到的是平台自己的「工作空间已停止 / 立即启动」页面（错误码 12809），
> **不是我们的产品**。这个页面靠请求唤不醒，只能点「立即启动」或重新部署。
>
> 如果他点开看到的是那个页面，**这一份记录作废**——那不是产品问题，是运维问题。
> 所以访谈第一句先确认：他看到的页面顶部有没有「◈ StackPilot」。没有就先点「立即启动」再开始。
>
> 具体预热步骤见 `docs/final-test-execution-manual.md` §2。

### 流程（每人 20–25 分钟）

| 段 | 时长 | 做什么 | 你在干什么 |
|---|---|---|---|
| ① 筛人 | 3 min | §3.1 三个筛人问题 | 判断他是不是目标用户（决定进不进分母） |
| ② 开场 | 1 min | 照读开场话术 | 只读，不补充 |
| ③ 让他自己用 | 8 min | 他自己输入 → 看追问 → 回答 → 看方案 | **闭嘴**，只记录 |
| ④ 提问 | 8 min | §3.3 主问句 + 追问 | 逐字照读 |
| ⑤ 收尾 | 2 min | §3.5 | 记原话 |

### ③ 这一段最容易搞砸

- 他输入完卡在追问页，**不要提示"下面还有几个选项"**。他找不到就是界面问题，记下来。
- 他问"这个要选哪个？"，**只回"你觉得呢"**。替他选等于替他做完了整件事。
- 他点了「high / medium / low」演示 tab，**记下来**。说明他不敢用自己的话试，先看样例——这本身是个信号。
- 他点了「我要自己填表」，**记下来**。说明解析层对他失效了，这是解析层的失败样本，价值很高。
- 他中途说"这啥意思"，**不要解释**，记下那个词，继续等。

## 3. 测试问题清单

### 3.1 筛人（照读）

1. 你手上有没有一个想做但还没开始的东西？一句话说说是什么。
2. 这个东西你打算自己写代码，还是找人写 / 用现成工具拼？
3. 你现在最卡的是"不知道用什么技术"，还是"知道用什么但不会写"？

> **判定**：第 1 题答不出具体东西 → `进分母 = 否`（没有动机，属 B0 样本问题）。
> 第 3 题答"知道用什么但不会写" → 仍然进分母，但记录时要标出来：他本来就不需要选型。

### 3.2 让他自己用（不提问，只观察）

不设问题。这一段只填 §4 的「使用过程」栏：

- 输入原文（**逐字抄，不要改写**）
- 产品读了哪几项（页面上"我读到了"那几行）
- 问了他哪几个问题
- 他答了几个、跳过几个
- 他有没有点演示 tab / 手动填表
- 从输入到看见方案用了多久

### 3.3 主问句（逐字照读，按顺序）

**第 1 问（主问句，决定达标）**

> 你看完这个方案，今晚会去做的第一步具体是什么？

**三个追问（借 M0 的 D4 三问，只在他答得含糊时用）**

- 若含糊 → 「今晚具体打开哪个网站、做什么动作？」
- 若说"再想想 / 先调研" → 「那今晚会打开什么？」
- 若说"找个人问问" → 「问完之后你会打开什么？」

**第 2 问**

> 如果你现在要放弃这个方案，最可能是因为哪个卡点？

- 若说"太难了" → 「难在"看不懂它说什么"，还是"看懂了但做不出来"？」
- 若说"感觉不太行" → 「是哪个部分让你觉得不太行，能指一下吗？」

**第 3 问**

> 方案里有没有哪个词 / 哪句话你没看懂？

- 若说"都懂 / 没有" → 「那这个方案里，你最不确定它到底是干什么的是哪一个？」

**第 4 问（本轮新增，只在第 1 问没拿到具体动作时问）**

> 你会照着开始吗？不会的话，卡在哪？

### 3.3.1 第 4 问为什么排在第 1 问之后，而不是并进去

这是本轮设计上最容易做错的一处。

「你会照着开始吗」是一个**可以回答"不会"的问题**。如果一上来就问，等于主动递了个台阶，
对方顺着台阶说"不太会"，你就永远拿不到第 1 问那个真正有信息量的答案——
**"我今晚会打开 supabase.com 注册账号"**。

所以顺序是：

```
第 1 问（要动作）──→ 拿到了具体动作 ──→ 判达标，第 4 问可以跳过
                 └─→ 拿不到 ──────────→ 第 4 问（要卡点），拿归因
```

第 4 问的价值不在于"会不会"，而在于**"卡在哪"这四个字会逼出一句具体的话**。
常见的三种回答，对应三种完全不同的处置：

| 他说的 | 真正的问题 | 归因 |
|---|---|---|
| 「不知道从哪下手」 | 方案的第一步不够具体 | 输出层 |
| 「这些名词我都不认识」 | 没看懂 | 看不懂 |
| 「我觉得没必要搞这么复杂」 | 不认同架构 / 或本来就超纲 | 不认同 / 解析偏差 |

**注意**：如果他说"不会"，接着追问"卡在哪"，他答了一个**产品层面的具体问题**（比如"我不知道 Supabase 和 Vercel 哪个先注册"），
这一份仍然判 `未达标`——**但不能归因给"输出层假设不成立"**，要归因给"第一步的可执行性"。
这两件事修法完全不同。

### 3.4 案例专属题（可选，只在时间够时问）

沿用 M0 的三组（`docs/interview-question-list.md` §四），但**必须放在 §3.3 全部问完之后**。
它们是引导性的，先问会把第 1 问的答案喂掉。

### 3.5 收尾

1. 如果我按你的意见改完，再给你看一次，你愿意吗？
2. 你身边有没有跟你情况差不多、也在想做点东西的人？

### 3.6 绝对不能问的

| 不能问 | 为什么 |
|---|---|
| 「你觉得这个产品怎么样？」 | 社交礼貌，必答"挺好的" |
| 「是不是比你自己找资料方便？」 | 逼他做对比，等于替他下结论 |
| 「这个方案对不对？」 | 你不是在测对错，是在测他会不会动 |
| 「你听懂了吗？」 | 他会答"懂了"，然后什么也不做 |
| 任何带"是不是因为……"的句子 | 那是你在给答案，不是他在说 |

```markdown
**他想做的东西**（他自己的一句话，逐字）：

**使用过程**

- 输入 → 看见方案：___ 秒

**引擎 Top1**：___（C__）
**方案的第一句第一步**（照抄）：

- 半步 = 说出了动作，但动作是"再查一下 / 再想想 / 问问别人 / 先学一下 XX"（决策动作，不是建设动作）
- 未达标 = 说不出来，或明确说不会照着做

**第 2 问：放弃最可能因为哪个卡点？**
> 原话：

**第 3 问：哪个词 / 哪句话没看懂？**
> 原话：

**第 4 问（第 1 问没拿到动作时才问）：你会照着开始吗？不会的话卡在哪？**
> 原话：

**主因**（六选一，按 framework §5.2 的优先级判，命中即停）：
看不懂 / 不认同架构 / 不信任 / 能力不匹配 / 没有动机 / 解析错误 / 其他

**解析偏差**（这一栏只有终测有）
- 他说的和产品读到的，有没有对不上的地方：
- 有没有该读到的没读到（漏读）：
- 有没有读反的（极性）：
- 有没有该问的没问 / 不该问的问了：

**进分母**：是 / 否（理由：）
```

### 4.1 「解析偏差」这一栏怎么填

拿三样东西对：**他的原话**、**页面上的"我读到了"**、**追问了哪几个**。

| 现象 | 填法 | 后续动作 |
|---|---|---|
| 原话里明确说了 A，产品没读到 A | 漏读 | 记下来，这是解析层 bug |
| 原话里明确说了"不要 A"，产品读成"要 A" | **极性读反** | 最高优先级 bug（本轮刚修过一次同类） |
| 原话里没说 A，产品自己填了 A | 幻觉 / 过度推断 | 违反"你没说的我不替你猜"，记下来 |
| 产品问了他刚刚才说过的事 | 追问冗余 | 体验问题，会让人觉得"它没在听" |
| 产品问了一个他根本不可能知道的问题 | 问题超纲 | 比如问非技术用户"要不要 RLS" |

> 这一栏的每一条都要单独提 issue，**不要混进 p 的计算里**。
> 因为 p 测的是"输出层假设"，解析层的 bug 修完之后 p 会变，两轮数据不可直接比较。

## 5. 判定口径

与 `docs/interview-analysis-framework.md` **完全一致**，不新造标准。

### 5.1 三档定义

| 档 | 定义 | 算不算分子 |
|---|---|---|
| **达标** | 说出了**今晚就能做的具体动作**，且指向方案第一步，不需要再问人 | ✅ 算 |
| **半步** | 说出了动作，但是决策动作（再查 / 再想 / 问人 / 先学） | ❌ 不算（只做辅助观察） |
| **未达标** | 说不出来，或明确说不会照着做 | ❌ 不算 |

> "具体动作"的判定口径（照 M0 的，不改）：
> **打开哪个网站 / 装哪个东西 / 跑哪条命令 / 注册哪个账号**。
> "去学 React" 不算具体动作——那是能力建设，不是这一晚能做完的一步。

### 5.2 进分母规则

| 情况 | 进分母 | 理由 |
|---|---|---|
| 正常完成 | 是 | |
| 筛人第 1 题答不出具体想做的东西 | 否 | 没有动机，属 B0 样本问题 |
| 中途离场 / 没看完方案 | 否 | 没看到材料，测不到 |
| 你没按纪律（替他操作 / 替他解释 / 先问了案例专属题） | 否，但保留为参考 | 流程问题，不是产品问题 |
| **产品崩了 / 打不开 / 解析层直接报错** | **是** | 这是产品失败，不能剔掉凑好看数据 |

最后一条是终测新增的，因为 M0 没有"产品会崩"这种可能。
**产品挂了必须算失败，不能算"样本无效"。** 否则越崩 p 越高，这就是在自欺。

### 5.3 算 p

```
n = 进分母 = 是 的份数
k = 其中 达标 的份数          ← 半步不算
p = k / n                     ← 保留两位小数
```

### 5.4 两档验收线

| 档 | 条件 | 结论怎么写 |
|---|---|---|
| **方向性成立** | n=5 时 k ≥ 3（p ≥ 0.60） | 「方向性支持」，**不写**「验证通过」 |
| **M1 验收通过** | n=10 时 k ≥ 6（p ≥ 0.60） | 「M1 输出层达标」，仍不写「效果承诺」 |

为什么两档都要：n=5 只能区分"明显成立"和"明显不成立"（framework §7 已经算过，
p=0.20 和 p=0.60 的 95% 区间大幅重叠）。**5 人过线只是允许你继续，不是允许你宣布成功。**

### 5.5 结论的写法

正确：

> 10 人中 6 人能说出今晚的具体第一步（p=0.60），方向性支持"给方案能促使人动手"。
> 3 人卡在"不知道 Supabase 和 Vercel 哪个先注册"，属第一步可执行性问题，不是架构不认同。

错误：

> 验收通过，用户认可度 60%。

（"认可"是错词，我们测的是动作；"验收通过"要看走的是哪一档。）

## 6. 样本量与画像配比

| 画像 | 人数 | 为什么要有 |
|---|---|---|
| 非技术（不会写代码） | 3 | 最可能卡在"看不懂"，是输出层的压力测试 |
| 半技术（会一点，能改别人代码） | 4 | **主目标用户**，p 主要看这一组 |
| 全栈（能独立做完整项目） | 3 | 对照组：他们不需要选型，如果他们也不达标，说明问题在别处 |

**不要挑人。** 为了把 p 做上去而只找"半技术里比较机灵的"，数据直接归零（framework §8 反模式 #7）。

**案例覆盖**：不强制每个技术栈都覆盖到，但要求 **Top1 至少出现 3 种不同结果**
（否则你测的是"一套方案的 10 种反应"，不是"产品的 10 种反应"）。

### 6.1 实测：只有 3 种结果，不是 12 种（2026-10-24 跑全部 10 个案例）

用同一份"标准答法"（JS 熟练 / 对外做产品 / 只有我一个）把 10 个案例全跑了一遍完整链路：

| 案例 | 解析层读到 | 完整链路 Top1 |
|---|---|---|
| H01 / H04 | `web`+`ai` ／ `selfhost`+`ai` | **C11** Next.js 纯前端 + Edge Functions |
| H02 / H05 / H06 / H08 | `web` +（`no_persistence` 或空） | **C12** Vite + React 纯静态 |
| H03 / H07 / H09 / H10 | 覆盖不了 | **不出方案** |

原因是解析层通常只从原文读到 2 项，剩下 7 项全靠追问三题。
**所以 Top1 的差异主要来自"追问三题的答案"，不来自原文。**

三条直接后果，会改变你怎么安排访谈：

1. **案例分配改成 H01 / H06 / H03**（分别对应 C11 / C12 / 不出方案），
   详见 `docs/final-test-execution-manual.md` §3。

## 7. 现场纪律（每次访谈前逐条打勾）

- [ ] 让他自己输入，**我不碰键盘**
- [ ] 他卡住时**不提示界面怎么用**
- [ ] 他说"这啥意思"时**不解释**，只记那个词
- [ ] 给完方案**留 60 秒沉默**，不打破
- [ ] **不问**"你觉得怎么样 / 有没有用 / 靠不靠谱"
- [ ] 他说技术判断时**不辩护、不纠正**
- [ ] 主问句**逐字照读**，不改词
- [ ] 第 4 问**只在第 1 问没拿到动作时**问
- [ ] 全程**录音或速记原话**，不当场总结成"他觉得太重"
- [ ] 访谈中**不打开** `interview-analysis-framework.md`

## 8. 一页纸速查（打印带走）

| 步骤 | 做什么 | 得到 |
|---|---|---|
| 1 | 筛人三问 | 进不进分母 |
| 2 | 让他自己用 8 分钟，我闭嘴 | 输入原文 / 读到了什么 / 问了什么 |
| 3 | 第 1 问：今晚第一步是什么 | 达标 / 半步 / 未达标 |
| 4 | 没拿到动作 → 第 4 问：会开始吗？卡在哪 | 主因 |
| 5 | 第 2、3 问 | 主因（交叉验证） |
| 6 | 数 n（剔除非分母）、数 k（半步不算） | n, k |
| 7 | p = k / n | 走 5.4 的两档线 |

**四个数字就够了：n、k、p、主因分布。**
其余都是解释，不要写进结论。
