# ADR-002：产品定位转向 Vibe Coding，主形态改为 MCP Server

| | |
|---|---|
| **状态** | 已采纳（Accepted） |
| **日期** | 2026-10-24 |
| **取代** | ADR-001 里"M1 之后继续做 Web 输出侧验证"的路线（不是推翻结论，是换了主形态） |
| **影响范围** | Schema（`skills` → `ai_workflow`）、打分权重表、解析层追问、解释层输出物、交付形态 |

---

## 一、这个 ADR 要回答什么

两件事，一句话一件：

1. **目标用户变了。** 从"自己写代码的人"改成"用 Cursor / Agent 写代码的人（Vibe Coder）"。
2. **主形态变了。** 从"用户打开网页输入需求"改成"用户在 Cursor / Claude Code 里调一个 MCP 工具"。

Web 页面**不删除**，降级为调试台。

---

## 二、为什么转（触发点）

### 2.1 用户的一句话

> 我不会写代码，只想用 Cursor 自然语言让 AI 帮我写，我该选什么技术栈？

旧版给的是 **C12 Vite + React 纯静态（零后端）**。

### 2.2 但原因不是我们最初以为的那个

第一反应是"因为 `skills` 全是 0，所以排除了带数据库的方案"。实测推翻了它：

| 实验 | 结果 |
|---|---|
| 同一句需求，技能全 0 vs 技能中等 | Top1 **都是 C12 4.73**，C01 **都是 4.05**，一分不差 |
| C01（Next.js + Supabase）的硬排除条件 | 只有小程序 / 支付合规 / 用户数 > 1 万，**跟 skills 无关** |

真正的三股力，按贡献排序：

1. **`goal_type` 缺失 → 权重回落到 `internal_tool`**（`learning 0.39` 最重），极简方案天然占优。
   这股力最大，而且完全看不见。
2. **fit 天花板不对称**：C11/C12 有一条 `not_contains auth/file` 规则，需求为空时必然命中 →
   fit 直接 clamp 到 5（乘数 1.00）；C01 的 base fit 是 4，**加满也只有 4.45**，数学上赢不了 4.73。
3. skills=0 只排除了 C02/C03/C09，这三套本来也进不了 Top2。

**结论：光删 `skills` 字段，产品行为不会变。** 这条结论决定了后面的改法——必须动权重和 fit。

---

## 三、考虑过的三个方案

### 方案 A：只删 `skills` 字段，不动别的

- 改动：`combos.json` 里 9 条规则
- 后果：**Top1 完全不变**（见 §2.2）。等于没改。
- 否决理由：解决不了任何实际问题。

### 方案 B：加一个布尔字段 `is_vibe_coding`，为真时走特殊分支

- 改动：新字段 + `computeConfidence` 的 9 字段口径 + 追问模板 + 前端表单 + 全部标注数据
- 后果：一个布尔无法表达"AI 写多少"的程度差异（全自动 / 人改 / 想学，三者的最优架构不同）
- 否决理由：**信息量不足**，且改动面比枚举更大。

### 方案 C（采纳）：`ai_workflow` 三档枚举 + 权重表按它索引

- `skills` 整体废弃 → `ai_workflow: 'full_auto' | 'assisted' | 'learning'`
- `ScoreDims.learning` → `ai_friendliness`，12 套重新评分
- **`WEIGHTS` 的索引从 `goal_type` 改为 `ai_workflow`**
- 删掉 3 条 skills 硬排除，新增 8 条 ai_workflow fit 规则

**为什么权重按 ai_workflow 索引，而不是继续按 goal_type**：
旧表假设"做产品 vs 内部工具"决定该看重什么。但新定位下真正决定"该看重什么"的是**谁写代码**——
`full_auto` 的人不关心学习成本，只关心 AI 一次能不能写对；`learning` 的人恰恰相反。
这样两件事分开了：**权重 = 工作方式，fit = 具体需求**。`goal_type` 没消失，它仍通过 fit_rules 生效。

## 四、采纳后的效果

同一句需求（"我不会写代码，只想用 Cursor 自然语言让 AI 帮我写"）：

| | 改前 | 改后 |
|---|---|---|
| Top1 | C12 纯静态 **4.73** | **C01 Next.js + Supabase 4.88** |
| 候选数 | 8（C02/C03/C07/C09 被排除） | 11（只剩 C07 因小程序被排除） |
| 排除原因 | 含 2 条"SQL/Python 基础不足" | 无一条因基础不足 |

第二行和第三行是这次转向的实质：**"你不会 SQL"不再是排除带数据库方案的理由。**

## 五、为什么主形态改成 MCP

### 5.1 Web 形态的三个硬伤（实测）

1. **路径被网关改写**：部署平台的网关把所有路径压成 `/`，被迫做单路径折叠适配。
2. **沙箱 10–15 分钟自动休眠，且 HTTP 唤不醒**：用户点开链接看到的是平台自己的"工作空间已停止"页。
3. **没有环境变量注入入口**：凭据只能随产物上传——这是致命安全问题，已因此下线该部署。

### 5.2 MCP 形态解决的是同一批问题

| 问题 | MCP 下 |
|---|---|
| 用户得先打开一个网页 | 在他已经在用的编辑器里，一句话调起 |
| 要把需求重新打一遍 | 上下文已经在对话里 |
| 拿到方案还要自己复制粘贴 | 返回的就是可直接粘给 AI 的启动 Prompt |
| 部署、休眠、凭据 | 都在用户本机，跑 stdio，不经过任何服务器 |

**最关键的一条**：这个产品的输出物本来就是"给 AI 的指令"。放在网页上，用户还得复制；
放在 MCP 里，工具返回的就是下一步的输入。**形态和产物对齐了。**

## 六、后果（写清楚，不装作没有）

### 6.1 好的

- 选型结论与产品定位一致了（见 §4）
- 输出物从"给人看的解释"变成"给 AI 的指令 + 给人的解释"，两段分工明确
- 无 key 也能用（关键词规则 + 模板兜底），采用门槛降到零

### 6.2 代价与风险

| 代价 | 说明 |
|---|---|
| **历史基线不可比** | D1 的 10 条帖子写于 `ai_workflow` 存在之前，没有一条提"谁写代码"，所以核心组必缺这一项 → 最高只能到 **medium**（H01 从 high 降下来） |
| **`ai_friendliness` 是主观打分** | 12 个数字没有任何实测支撑，已在 `combos.json` 标注"待真实用例校准" |
| **Web 调试台留了死代码** | `web/app.js` 里 14 处 `skills` 分支不再可达，故意不删（改坏调试台的代价更大） |
| **MCP 只在 SDK 客户端验过** | 没用真实的 Cursor / Claude Desktop 端到端跑过 |

### 6.3 明确不做的事

- **不删 Web 页面**。它是调试台，跑 `npm run dev` 就能用，改渲染逻辑时比走 MCP 快得多。
- **不为"无 key 模式"打磨文案**。那只是兜底路径，配了 key 走 LLM 就不会出现。
- **不改 PRD**。PRD v0.4.4 里还写着 `skills.js` 的示例，属于已知文档债——改它要重走一遍版本，收益不抵成本。

---

## 七、什么情况下应该回滚

不是"以后觉得不对就回滚"，是这三条具体信号：

1. **真实 Cursor 用户装完之后的调用率 < 20%**（装了但不用）→ 说明"在编辑器里问架构"这个场景不成立，回 Web。
2. **`ai_friendliness` 校准后发现与主观打分排序冲突 ≥ 4 套** → 权重表的根基是错的，要重评而不是微调。
3. **`full_auto` 用户里超过一半仍然被推 C12** → 说明 fit 通道压不住 base_scores，得改公式而不是调 delta。

---

## 八、这份 ADR 引用的证据

| 结论 | 证据来源 |
|---|---|
| skills 不影响 C01 分数 | 对照实验：技能全 0 vs 中等，C01 都是 4.05（见 `docs/vibe-coding-pivot.md` §1.2） |
| fit 天花板 4.45 | C01 base fit=4，加满到 5 时 `4.45 × 1.00`；C11/C12 因 `not_contains` 直接 clamp 到 5 |
| 改后 Top1 = C01 4.88 | `npm run mcp:smoke` 的真实输出（`out/mcp-smoke-output.md`） |
| 3 条 skills 硬排除已删 | `check-consistency` 第 3 节的"防止半迁移/回退"断言 |
| D1 历史数据无 ai_workflow | 10 条原文的关键词扫描：`Cursor`/`AI 帮我写`/`不会写代码` 命中 0 |
